# Notivelle — план MVP

Согласован 2026-10-12.

## Цель

Редактор Markdown в духе Obsidian, но для **отдельных файлов**, без vault.

MVP одной фразой: Notivelle стоит приложением по умолчанию для `.md`. Дабл-клик по файлу
открывает его вкладкой в уже запущенном окне, где его можно править в Live Preview с
callouts, формулами и диаграммами, переключаться в Reading или Source и сохранять, не
боясь испортить файл.

## Стек и принципы

- **Tauri 2** (стабильная ветка 2.x, не 3.0-alpha) + **CodeMirror 6** + **TypeScript** (vanilla, без фреймворка) + Vite, npm.
- Платформы: в MVP только **Linux**. Код с самого начала кроссплатформенный (пути, CRLF);
  сборки под Windows и macOS делает GitHub Actions (`release.yml`), руками на этих
  системах они пока не проверялись.
- **Основная логика на Rust**, и Rust-код полноценный, а не минимальный: проект ещё и
  для изучения языка.
- **У JS нет прямого доступа к файловой системе.** Весь ввод-вывод идёт через наши
  Rust-команды; fs-плагин Tauri фронтенду не выдаём.
- Файлы сохраняются **байт-в-байт**: никакого переформатирования; переводы строк, BOM и
  финальный перевод строки остаются как были.
- Всё работает офлайн: шрифты, KaTeX и Mermaid лежат внутри приложения, CDN нет.

## Что входит в MVP

### Файлы
- Открыть файл можно аргументом командной строки, через Ctrl+O или перетащив его в окно.
- Командная строка (`cli.rs`, `pending.rs`): `notivelle [ФАЙЛ…]`, `--help`, `--version`.
  Путь с пробелами без кавычек собирается из частей. Из терминала релизная сборка
  уходит в фон (отдельная группа процессов, вывод в никуда), терминал сразу свободен.
- Без файлов программа начинает с пустого документа «Без названия», как Kate. Первое
  сохранение — диалог «Сохранить как» в Rust (имя предлагается по первой строке).
  Нетронутый пустой документ уступает место открытому файлу; после закрытия последней
  вкладки появляется новый пустой. Новый документ — Ctrl+N или «+» в полосе вкладок.
- Single instance: повторный запуск открывает файл вкладкой в уже запущенном окне (как Kate).
- Приложение регистрируется для `text/markdown` через `.desktop`-файл.
- Сохранение байт-в-байт: LF/CRLF, BOM, финальный перевод строки. Запись атомарная
  (временный файл, затем rename), права и симлинки сохраняются.
- Watcher: если файл изменили снаружи, чистая вкладка перезагружается сама, а на вкладке
  с правками появляется плашка «файл изменён на диске».

### Вкладки
- Таб-бар с пометкой несохранённых изменений, Ctrl+Tab и Ctrl+W, при закрытии вопрос «сохранить?».
- Если файл уже открыт, повторное открытие переключает на его вкладку.

### Режимы (свой у каждой вкладки, по умолчанию из настроек)
- **Source:** CM6 с подсветкой Markdown и кода в блоках.
- **Сворачивание разделов** в Source и Live Preview — как в Obsidian: стрелка слева от
  заголовка при наведении, на месте раздела «…» (`editor/heading-folds.ts`). Границы
  раздела даёт lang-markdown (foldService по заголовкам), свёрнутое хранит состояние
  редактора (`codeFolding`): своё у вкладки, сдвигается при правках, разворачивается,
  когда в раздел попадает курсор. С режимом чтения свёрнутое не делится.
- **Live Preview:** разметка скрыта везде, кроме элемента под курсором. Поддерживаются
  заголовки, жирный, курсив, зачёркнутый, inline code, ссылки, списки с кликабельными
  чекбоксами, цитаты, callouts, блоки кода (``` прячутся, вместо них язык и кнопка
  «Копировать»), hr, локальные картинки, формулы, диаграммы, строчный HTML (`<kbd>`,
  `<sub>` …) и законченные HTML-блоки. Стрелки вверх/вниз заходят в нарисованные блоки.
- **Таблицы в Live Preview** — как в Obsidian: всегда нарисованы, ячейка правится на месте
  (вложенный редактор CodeMirror с исходным текстом ячейки); Tab, Enter и стрелки ходят
  по ячейкам; «+» добавляет строку и столбец; ручки строк и столбцов открывают меню и
  перетаскиваются; правый клик — меню (вставить, переместить, дублировать, удалить,
  выравнивание). Правки меняют в исходнике только нужные символы.
- **Reading:** HTML, который рендерит Rust. Чекбоксы задач кликабельны и меняют текст.
  Разделы сворачиваются, как в Obsidian: стрелка слева от заголовка при наведении, щелчок
  прячет всё до следующего заголовка того же или более высокого уровня (`reading/folds.ts`).
  Свёрнутое помнится у вкладки и переживает правки (ключ — уровень, текст и номер
  заголовка, а не строка); переход по ссылке к заголовку разворачивает его разделы.
- Ctrl+E переключает Reading и последний режим редактирования; Ctrl+Shift+E — Source ↔
  Live Preview. Те же три режима — кнопками в строке состояния. Файлы открываются в
  Live Preview, как в Obsidian.

### Вики-ссылки (M8)
- `[[Заметка]]`, `[[Заметка|подпись]]`, `[[Заметка#Заголовок]]`, `[[#Заголовок]]`,
  вложения-картинки `![[кот.png]]`, `![[кот.png|300]]`, `![[кот.png|300x200]]`. Без
  подписи ссылка показывается как в Obsidian: «Заметка > Заголовок».
- Файл ищется по имени (`wikilinks.rs`): рядом с документом, по пути от корня хранилища,
  потом по имени во всём хранилище без учёта регистра (ближе к корню — раньше; скрытые
  папки пропускаются; не больше 20 000 записей). Хранилище — ближайшая папка выше
  документа с `.obsidian`, иначе папка документа.
- Reading: comrak разбирает `[[…]]` сам, а render.rs выводит `<a class="internal-link"
  data-wikilink>`; щелчок отдаёт цель в Rust (`open_wikilink`), к заголовку вкладка
  прокручивается во фронтенде. `![[…]]` comrak не разбирает — вложения ищутся в
  текстовых узлах и становятся `<img src="mdimg://…/имя?embed">`: файл по имени находит
  протокол при загрузке картинки, рендер по папкам не ходит.
- Live Preview: свой узел lezer `WikiLink`/`WikiEmbed`; Ctrl+клик открывает, картинки —
  виджетом. Имя заметки в ссылке не проверяется орфографией.
- Пока нет: встраивания заметок целиком (`![[Заметка]]` — ссылка), подсветки ссылок на
  несуществующие заметки, создания заметки по щелчку, автодополнения `[[`.

### Callouts
`> [!type] Заголовок`, сворачивание через `+`/`-`, все стандартные типы Obsidian с
алиасами. Неизвестный тип показывается как `note`.

### KaTeX
- `$...$` для формул в строке, `$$...$$` для отдельного блока.
- Reading: comrak (`math_dollars`) только помечает формулы, а рисует их KaTeX во
  фронтенде. Одна библиотека в обоих режимах, поэтому формулы выглядят одинаково.
- Live Preview: своё расширение парсера lezer для `$`/`$$`, отрендеренная формула как
  виджет, при курсоре внутри виден исходник. Блочные формулы через `StateField`.

### Mermaid
- Блоки ```` ```mermaid ```` превращаются в SVG и в Reading, и в Live Preview.
- Библиотека подгружается только когда в документе есть диаграмма.
- SVG кешируется по хешу текста диаграммы; перерисовка при смене темы.
- `securityLevel: 'strict'`.

### Проверка орфографии
- Своя, на Rust, через крейт `spellbook` (совместим с форматом Hunspell).
- Словари ru_RU и en_US лежат внутри приложения (`src-tauri/dictionaries`, источник и
  лицензии — в README там же).
- Язык выбирается для каждого слова по алфавиту: кириллица — ru, латиница — en.
- Проверяются только видимые слова вне кода, ссылок, формул и frontmatter.
- Наше контекстное меню: варианты исправления и «добавить в словарь». Личный словарь
  хранится в каталоге конфигурации.

### Прочее
Поиск и замена (Ctrl+F), Vim mode в настройках, светлая и тёмная тема (по умолчанию
как в системе), конфиг в TOML плюс простая панель настроек (шестерёнка в строке
состояния, Ctrl+,). Цвета тем — `light-dark()` в CSS (нужен WebKitGTK 2.44+ /
Safari 17.5+). Шрифты, как в Obsidian, — три отдельных: интерфейса, текста и
моноширинный. Список шрифтов системы собирает Rust (`fontdb`), моноширинные и
символьные шрифты определяются по глифам; можно выбрать и общие семейства
(`system-ui`, `serif`…), которые настроены в fontconfig.

### Сборка и установка (M7)
Программа называется **Notivelle**, идентификатор `dev.maksim.notivelle`, бинарник
`notivelle`. Tauri собирает deb и rpm со своим шаблоном `.desktop`
(`src-tauri/linux/notivelle.desktop`: `Exec=notivelle %F`, `MimeType=text/markdown`,
подписи по-русски). Для Arch и Omarchy — `packaging/arch/PKGBUILD`: собирает
закоммиченное состояние репозитория и берёт готовое дерево `/usr` из deb. Иконка —
`src-tauri/icons/source/notivelle.svg`, остальные размеры из неё делает `tauri icon`.
При первом запуске настройки и личный словарь переезжают из каталога прежнего
имени (`dev.maksim.md-editor`, модуль `migration`). Подробности — `packaging/README.md`.

Лицензия — MIT (`LICENSE`). GitHub Actions: `ci.yml` (проверки на Linux, Windows,
macOS) и `release.yml` (по тегу `v*`: установщики Windows NSIS/MSI, универсальный DMG
для macOS, `.pkg.tar.zst` для Arch из `makepkg` в контейнере — в черновик релиза, который
публикуют руками; id черновика берётся из ответа на его создание, а не из списка релизов:
список обновляется с задержкой, и в v0.2.0 установщики из-за этого в релиз не попали). Настройки бандлов для
Linux — в `tauri.linux.conf.json`, для Windows — в `tauri.windows.conf.json` (MSI на
русском, кодовая страница 1251: иначе WiX не записывает кириллическое описание типа
файла); на macOS файлы из Finder приходят событием `RunEvent::Opened`, а не
аргументами.

## Что сознательно не входит

Outline/TOC, восстановление сессии, недавние файлы, экспорт в HTML/PDF,
кодировки кроме UTF-8, несколько окон, подпись установщиков для Windows и macOS. HTML-обёртки
вокруг Markdown (`<div align="center">` … `</div>`) в Live Preview остаются текстом
(в Reading рендерятся). Выделение нескольких ячеек таблицы мышью.

## Архитектура

### Rust (`src-tauri/src/`)

| Модуль | Что делает |
|---|---|
| `document` ✅ | Проверяет UTF-8, определяет BOM и тип переводов строк, восстанавливает их при сохранении |
| `disk` ✅ | Атомарная запись (`tempfile` + `fsync` + rename), права, симлинки, лимит размера 32 МиБ |
| `documents` ✅ | Реестр открытых документов: фронтенд знает только `DocumentId`, путей не передаёт; проверка, не изменился ли файл на диске перед сохранением |
| `dialogs` ✅ | Системные диалоги из Rust: открытие файла, «Сохранить изменения?», «Файл изменился на диске» |
| `pending` ✅ | Очередь файлов на открытие: командная строка, повторный запуск (single instance), перетаскивание в окно; фронтенд забирает её по событию `files-pending` и при старте |
| `watcher` ✅ | `notify` следит за папками открытых файлов (атомарные сохранения подменяют файл); события копятся, пока по файлу не станет тихо, потом файл сверяется по содержимому — свои сохранения так не считаются чужими; событие `disk-change` во фронтенд |
| `render` ✅ | `comrak` (GFM, формулы, сноски, `==выделение==`, frontmatter скрыт, `data-sourcepos`), в AST превращает blockquote в callout (сворачиваемые — через `<details>`), санитайзинг через `ammonia` |
| `assets` ✅ | Протокол `mdimg://` для локальных картинок по путям относительно документа (только файлы-картинки), вложения `?embed` ищутся по имени; пути из ссылок |
| `wikilinks` ✅ | Вики-ссылки: разбор цели (`Заметка#Заголовок`), вложения `![[…]]` в тексте, размер картинки, поиск файла по имени в хранилище Obsidian или папке документа |
| `callouts` ✅ | Реестр типов и синонимов Obsidian, разбор маркера `[!type]±`; иконки (Lucide) — во фронтенде |
| `spellcheck` ✅ | `spellbook`, словари вшиты в программу и разбираются в фоне, выбор языка по алфавиту, «ё» необязательна, личный словарь |
| `migration` ✅ | Перенос каталога конфигурации со старого имени программы (md-editor → Notivelle); переименование, а между файловыми системами — копирование |
| `config` ✅ | `settings.toml` через `serde`/`toml` в каталоге конфигурации; недостающие ключи — по умолчанию; испорченный файл не мешает запуску и перед перезаписью копируется в `.bak` |
| `error` ✅ | Общий `AppError` через `thiserror`, во фронтенд уходит как `{ kind, message }` |
| `commands` ✅ | Tauri-команды; дисковые операции и диалоги — в отдельном потоке (`spawn_blocking`) |

### TypeScript (`src/`)

Настройка CM6, плагин Live Preview (декорации поверх дерева lezer), виджеты callouts,
формул и диаграмм, плагин проверки орфографии, менеджер вкладок (один `EditorView`
и отдельный `EditorState` на вкладку), отображение Reading, диалоги, хоткеи.

### Порядок рендера в Reading
Markdown → comrak (AST, callouts) → HTML → ammonia → DOM → KaTeX для формул и
Mermaid для диаграмм (они рисуют уже после санитайзинга, в строгом режиме).

## Риски и компромиссы

- **Два парсера:** Live Preview парсит через lezer (JS), Reading через comrak (Rust). На
  редких конструкциях результат может немного различаться. В Obsidian так же.
- **CSP:** Mermaid вставляет `<style>` внутрь SVG, поэтому `style-src` разрешает
  `'unsafe-inline'`, а подстановка nonce в `style-src` отключена
  (`dangerousDisableAssetCspModification`). Скрипты остаются под nonce.
- **WebKitGTK + NVIDIA** (на машине гибридная графика Intel + RTX 3060): подтвердилось на
  M0 — `Error 71 (Protocol error) dispatching to Wayland display`. Решено в
  `src-tauri/src/main.rs`: на Linux первой строкой `main` выставляется
  `WEBKIT_DISABLE_DMABUF_RENDERER=1`, если пользователь не задал её сам. Это единственный
  `unsafe` в проекте (`set_var` в edition 2024), с обоснованием `// SAFETY:`.
- **M4** — самый объёмный этап: Live Preview с виджетами формул и диаграмм.
- **Смешанные переводы строк** (CRLF и LF в одном файле) байт-в-байт не сохранить:
  редактор хранит строки с `\n`. При сохранении все переводы приводятся к самому частому
  виду; об этом предупреждает уведомление при открытии и пометка «смешанные» в строке
  состояния. Сохранение без правок файл
  не трогает.
- **Атомарное сохранение** заменяет файл новым: жёсткие ссылки на него и расширенные
  атрибуты (xattr, ACL) не сохраняются. Права и симлинки сохраняются.
- **Фокус при повторном запуске на Wayland:** композитор может не отдать фокус окну без
  токена активации (xdg-activation). Тогда файл откроется вкладкой, но окно лишь
  подсветится как требующее внимания.
- **Перезагрузка страницы** (при разработке Vite делает её после правок кода) стирает
  вкладки во фронтенде. При старте фронтенд вызывает `restore_documents`, и Rust заново
  отдаёт открытые файлы с диска; несохранённые правки при этом теряются.
- **Внешние картинки** (`https:`) в режиме чтения грузятся из сети: по ним автор документа
  может узнать, что его открыли. Возможно, стоит сделать это настройкой (M6).
- **KaTeX:** `npm audit` сообщает об уязвимости низкой важности (обход `trust` при уже
  существующем загрязнении прототипов). `trust` мы не включаем; предлагаемое npm
  исправление — откат Mermaid на 10.8 — хуже самой проблемы.
- **Ссылки из режима чтения:** внешние открываются в браузере только для `http`, `https`,
  `mailto`; по относительным ссылкам открываются только Markdown-файлы.
